Reading the numbers: the prototype runs every tenant through one Python process with one lock, so it saturates once demand exceeds what a single core can process. Up to that point every request succeeds and nothing is lost; past it, latency grows rather than data being dropped, because collectors keep payloads in their outbox until acknowledged. The production path (stateless ingest behind a queue, AIOps workers sharded by series) removes the single-process ceiling; see ARCHITECTURE.md section 8.
